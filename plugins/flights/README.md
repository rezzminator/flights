# flights

Claude Code plugin for the flights agents that build and land work — two foremen, a lander with its three reviewers, a speccer, a tracer that answers questions from code, a read-only diff reviewer, /flights:spec and /flights:doctor — and a codebase map, ponytail's symbol map ported: one line per source folder naming its exported functions, classes and types, within 2,000 characters, given to the main chat and the flights builder agents at their start, cached per commit.

The agents, each spawned as `flights:{name}`: `flights:foreman` (Opus) and `flights:foreman-sonnet` (Sonnet, the same manual) build one request each; `flights:lander` takes their worktree to merge-ready, spawning the review its kit `flights:lander-inventory` computes from `flights:diff-checker`, `flights:spec-checker` and `flights:usage-checker`; `flights:speccer` designs novel work through `/flights:spec`; `flights:tracer` answers numbered questions from code through `flights:sub-tracer` readers and its kit `flights:tracetree`, its callers' manual `/flights:trace-guide`; `flights:reviewer` reviews a diff of any size read-only, spawning the same computed review; `/flights:doctor` measures a flight. They hand git writes and prompt and doc edits to Professor's agents (`gitter`, `pcm`, `documenter`) and `/flights:doctor` reads runs through Professor's `pfm`.

At each `SessionStart` of the main chat, and at the `SubagentStart` of the agent types `flights:foreman`, `flights:foreman-sonnet` and `flights:lander`, the session's git repository is mapped by ponytail's codebase map, ported to Python: one line per folder of tracked source files, `{folder}/: {names}`, naming the top-level functions, classes and exports its files define (each file's first 3, 1 each in a folder of more than 8), shared code first, within 2,000 characters, then `(N more folders not listed)`; tests, generated and vendored files are skipped, and a repository whose source files name nothing gets no map. Ponytail's MIT notice is in `THIRD_PARTY_NOTICES.md`. In a linked git worktree the map holds only the lines of the folders that worktree changed since its merge-base with the main worktree's `HEAD`, committed, uncommitted or untracked, under the header `Codebase map of the folders this worktree changed (…)`; a folder holding only untracked files has no line, and a worktree whose changes reach no folder with a line, or whose changes git could not read, gets the full map. The map is cached per commit under `${XDG_CACHE_HOME:-$HOME/.cache}/flights/map/`, one build shared by every work tree at that commit, so another tree at the same commit can see a dirty tree's names rather than the commit's; each build removes cache files older than 7 days. A map that cannot be built is said in one `Codebase map unavailable: {reason}` line; outside a git repository nothing is added. The hook answers within 4.5 seconds and has no settings.

Install with `claude plugin install flights@professor` after `claude plugin marketplace add rezzminator/flights`. Needs `python3` 3.9 or later and `git`. Limits: Claude Code only; the agents' hand-offs need Professor. Remove it with `claude plugin uninstall flights@professor`. Full documentation: <https://github.com/rezzminator/flights>
